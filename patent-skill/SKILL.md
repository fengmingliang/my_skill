# 专利创意交底技能

把技术创意推进到可提交交底书的六步闭环。每步都有产出物和"过关条件"，**不满足条件不得进入下一步**——跳步是本技能最常见的失败原因。

## 一、六步主线

| 步 | 动作 | 产出 | 过关条件 |
|---|---|---|---|
| 1 | 问题陈述 | 一页结构化陈述：要解决的问题、场景、初步方案、已知相关方案、待澄清点 | 场景边界清晰；现有手段失效原因讲成**因果链**而非罗列清单 |
| 2 | 方案推荐 | 选型对比表（含理由）、控制时序、安全逻辑 | 每个关键选型都有正反权衡；工程估算值与确定设计分开标注 |
| 3 | 现有技术检索 | 3–5 件主对比文件 + 背景谱系 + 非专利现有技术 | 覆盖硬件结构 / 控制方法 / 作业流程三方向；著录项齐全 |
| 4 | 差异对比 | 差异表 + "两两组合能否得到本案"拆解 + 核心创新点编号 | 每条差异落到具体技术特征；明确指出上位概念风险 |
| 5 | 取证设计 | 逐保护点取证表 + 维权分级策略 + 权要撰写对策 | 方法权要绑定外部可观测特征；不可见算法转商业秘密 |
| 6 | 交底书成稿 | 六章交底书（演示文稿或文档） | 保护点与有益效果同编号同序；校验后交付 |

## 二、贯穿全程的五条硬原则

1. **划清工况边界**：先区分本案针对的是哪种失效状态（如"浅陷打滑"与"底盘坐死陷死"完全不同）。对比、创造性、权要范围全部以此为基准。
2. **优先挖"复用原车部件当功能件"的发明点**：零新增硬件的复用（如缓冲块压实兼作刚性止挡）既降低工程成本，又最易构成创造性差异。
3. **反直觉时序是方法权要最强内核**：与直觉相反且有明确先后依赖的动作顺序（如"先把悬架缩回锁止、再整体举升"）比单纯硬件堆叠更难被规避。
4. **检索结论一律标注可信度**：渠道受限、著录项未查实、参数为估算，必须写明"待核实/待标定/待专业库复核"，不得写成定论。
5. **专利性结论只作初步判断**：终稿必须声明"最终以专利代理人及审查员意见为准"，不承诺授权。

## 三、执行纪律

- **不编造**：对比文件、公开号、申请人、数据一律来自检索结果；查不到就标"待核实"。
- **不迎合**：用户方案有明显缺陷（如单点支撑在软地必下陷、纯软件方案在附着力全失时失效）要直接指出并给替代方案。
- **参数纪律**：接地比压、举升行程、阈值角度等写"工程估算初值，待实车标定"。
- **检索降级要留痕**：专业库限流改走公开渠道时，在交底书"检索结果"章注明渠道限制，并给出正式提交前按 IPC 分类号复核的清单（常见：B60S 9/00 车辆举升、B60G 17/00 悬架调节）。
- **成稿复用本机 `ppt` 技能**：交底书做演示文稿时，先完整 Read `/home/user/.doubao/agent_mode/workspace/.skills/ppt/SKILL.md`，按其 Step 1–8 执行；示意图用可编辑原生元素（架构图、时序图、结构布置图），少用装饰图，全篇禁 emoji。

## 四、快速自检（交付前逐条过）

- [ ] 问题陈述是否呈现"失效链条"，而非缺点清单？
- [ ] 每个方案选型是否写了取舍理由？估算值是否标注待标定？
- [ ] 三个检索方向是否都覆盖？量产产品类非专利现有技术是否纳入？
- [ ] 是否逐条拆解了"对比文件 A+B 组合"的攻击路径？
- [ ] 是否识别出上位概念被占、概念已被产品公开两类新颖性风险？
- [ ] 方法权要是否全部用外部可观测特征表述？
- [ ] 内部阈值/算法是否已划入商业秘密、未写入专利？
- [ ] 保护点与有益效果是否同编号同序一一对应？
- [ ] 检索渠道限制、待补清单、免责声明是否齐全？
