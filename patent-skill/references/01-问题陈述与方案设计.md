# 第 1–2 步：问题陈述与方案设计

## 一、问题陈述的拆解框架

用户输入的专利创意材料通常含四段，逐段对应处理：

| 输入段 | 处理要点 |
|---|---|
| 技术背景 | 抽应用对象、产品量级（重量/尺寸/平台）、失效工况 |
| 现有技术及缺陷 | 每类手段写"原理 + 为什么失效"，不写形容词 |
| 要解决的技术问题 | 提炼出现有手段共同解决不了的那个缺口 |
| 发明目的 | 拆成可验证目标：硬件集成、时序联动、安全保护、闭环流程 |

### 把缺陷写成"失效链条"

错误写法（清单罗列）：
> 千斤顶易损伤底护板；空悬抬不起来；脱困板塞不进去。

正确写法（因果链）：
> 车轮空转刨蚀软地面 → 车身持续下沉 → 底护板坐地 → 车轮失去地面支撑 → 陷死；此时千斤顶单点受力易损护板且软地支点下陷、空悬只抬车架而车轮仍埋坑中、脱困板因轮胎下无间隙而无法塞入、漂浮/缓冲气囊工况与行程均不匹配。

链条式陈述的作用：直接指出本案必须跨越的物理障碍（如"底盘坐死后轮胎下方没有操作间隙"），后续创造性论证才有基准。

### 必须显式澄清的三类细节

信息缺失会直接影响权要布局，逐条问用户或给出"我的理解 + 请确认"：

1. **硬件构型**：单件还是多件？分区数？布置位置？收纳方式？是否影响正常离地间隙？
2. **核心机理**：各部件动作先后顺序；锁止/止挡/定型靠什么实现（气室封闭？机械锁？限高拉带？）
3. **触发与安全**：准入条件（车速/挡位/坡度/人员）；误触发防护；配套件是集成还是通用件

提问纪律：一次不超过 3 个问题；能推测的给默认值并注明"如无异议按此推进"。

## 二、方案推荐的选型维度

所有候选方案按下表逐项打分，输出表格 + 一句话结论：

| 维度 | 判断方法 |
|---|---|
| 承载与接地 | 按整备质量算接地比压（F/A），与目标地面（干沙/泥泞）的表层承载下限比较，判断支点是否会自沉 |
| 集成度 | 正常工况是否损失离地间隙；新增零部件数量；能否复用原车气源/液压源/控制器 |
| 可调能力 | 是否具备分区独立调压；是否有姿态闭环（高度传感器 + IMU） |
| 控制精细度 | 定时开停 vs 全过程闭环；泄压是瞬时还是分级受控 |
| 成本与平台适配 | 是否依赖昂贵主动硬件；能否下沉到中低配车型 |
| 失效安全 | 单点故障后果；有无超压、泄漏、低温、急停保护 |

### 两个高价值设计思路

1. **复用原车部件当功能件**：先在现有系统里找"已经在正确位置、已有正确强度、只是没被赋予该功能"的部件（如空悬缓冲块压实后即刚性止挡），实现零新增硬件的锁止。
2. **构造反直觉时序**：直觉方案（先抬车身）往往已被现有技术覆盖；反过来想"先改变车轮与车身的相对位置、再整体托举"，形成有先后依赖的两阶段时序，天然具备新颖性论证空间。

### 参数标注纪律

- 确定的**设计选择**（多腔、复用气源、护板联动）：直接写结论；
- 待验证的**数值**（举升行程、接地面积、充气时间、阈值角度、保压时长）：统一标"工程估算初值，待实车标定"；
- 估算过程要能复算：给出算式（如 35 kN / 2 ㎡ ≈ 18 kPa）而非只给结果。

## 三、方案输出的最小完整集

一份可进入检索的方案描述至少包含：

1. 系统组成（哪些模块、各自功能、与整车哪些系统耦合）；
2. 空间布置（装在什么位置、怎么收纳、正常工况是否影响通过性）；
3. 动作时序（编号步骤 + 前置条件 + 到位判据）；
4. 安全逻辑（准入条件、过程保护、异常中止）；
5. 人机分工（哪些自动、哪些必须人工，闭环终点是什么）。
