# 我的研究报告模板

固化的格式规范、配色系统和分析结构，确保每次输出风格一致、图文并茂、结论先行。

## 工作流程

### 1. 决策简报（先想清楚再动笔）

动笔前明确以下信息，能从上下文推断的不追问：

| 字段 | 要回答的问题 |
|---|---|
| 核心问题 | 这份报告要回答什么决策问题？ |
| 读者 | 谁会据此拍板？关注什么？ |
| 交付物 | 飞书文档？PPT？HTML可视化页？还是组合？ |
| 数据来源 | 已有哪些数据？需要补充搜索什么？ |
| 关键假设 | 哪些是推算值？哪些是已证实事实？ |

### 2. 证据底稿（事实门）

关键事实必须可追溯。为每条事实分配 ID（如 [F1]），记录：
- 原子事实内容
- 状态：已证实 / 推算 / 待验证 / 产品建议
- 直接来源（标题、发布方、日期、链接）
- 支持的结论

**事实闸门不通过的情况**：没有原始链接、数字无口径、把"即将推出"当现状、对比表无来源。不通过则删除该主张或降级为待验证。

### 3. 数据交叉核实与用户确认（核实门）

**本步骤为强制环节，所有关键数据必须通过后方可进入大纲设计。**

按 `references/data-verification.md` 执行：

1. **识别关键数据**：从证据底稿中提取所有具体数字、排名断言、政策条款、竞品参数，标记为"必须核实"
2. **双源交叉验证**：按行业权威平台映射表，在至少 2 个独立权威来源中核实每个关键数据
   - 汽车行业：太平洋汽车、易车、汽车之家、车主之家、乘联会、中汽协等
   - 其他行业：按 `references/data-verification.md` 中的映射表执行
3. **记录核实状态**：在证据底稿中为每条事实追加"来源1/来源2/核实状态"字段
4. **用户确认门**：遇到以下情况必须暂停，使用 `interaction.ask` 向用户确认后再继续：
   - 两个权威来源数据差异 >5%
   - 口径/定义/时间范围冲突
   - 核心结论依赖的数据无权威来源
   - 用户提供数据与公开数据冲突
   - 政策/法规不确定或存在多种解读
   - 涉及未公开的竞品敏感信息
5. **确认后记录**：用户选择后在证据底稿中记录"用户确认：选择X，时间"，确认数据方可进入正文

**核实门不通过的情况**：关键数据单源且无补充、矛盾数据未经用户确认、推算值未标注口径。不通过则该数据不得用于核心结论。

### 4. 大纲设计（演绎式结构）

按 `references/structure-template.md` 的标准章节组织：
开头 callout → 一图看懂 → 范围口径 → 现状趋势 → 核心分析（2-4节）→ 排除法反证 → 空间估算 → 行动建议 → 参考来源。

每节先给结论，再给证据。连续纯正文不超过500字，必须插入可视化元素。

### 5. 可视化制作

- **【强制规则】ECharts必须内联为单文件**：所有独立HTML数据可视化页面，必须将 `echarts.min.js` 的完整内容直接内联到 `<script>` 标签中，生成**完全自包含的单文件HTML**。**禁止使用外部文件引用**（无论是CDN还是相对路径`src="echarts.min.js"`），因为用户下载HTML后外部JS文件不会跟随，导致图表全部空白。交付前必须用headless Chromium截图验证图表正常渲染。
- **【强制规则】图表渲染自检**：生成HTML后必须用headless Chromium（`chromium-browser --headless --screenshot`）打开文件截图，逐张确认所有图表正常渲染（柱状图/折线图/饼图/环形图均可见、坐标轴和标签无重叠、文字无截断）。同时用 `node --check` 验证JS语法无错误。发现空白或错乱必须修复后重新验证，禁止未验证直接交付。
- **HTML5 block**（嵌入飞书文档）：复制 `assets/echarts-block-template.html`，替换数据和配置
- **独立HTML页面**：复制 `assets/data-viz-page-template.html`，包含KPI卡+多图表
- **表格**：用于精确对比，表头浅灰，数值右对齐，关键差异用红色标注
- **配色**：严格遵循 `references/format-spec.md` 的藏青色板
- **HTML布局对齐**：footer（参考来源、注释、分析人备注）必须与正文 `.container` 保持同样的 `max-width:1200px;margin:0 auto;padding:32px 24px`，整体块贴左边距，不居中、不贴屏幕边；正文与尾部内容的左右边界必须严格一致

### 6. 生成与校验

1. 用 lark-cli docs +script init-draft 初始化
2. 写入完整 XML（含 html5-block 引用）
3. 运行 parse 校验
4. 创建飞书文档
5. 回读确认：HTML5 block 数量、表格数量、callout 数量、章节结构

### 7. PPT 制作（如需要）

按 `references/ppt-spec.md` 的轻商务清爽风格：
- 白底、微软雅黑、深红标题左对齐
- 每页一观点，论证素材平均分布
- 10页左右：封面→核心结论→现状→市场→案例→空间→竞品→人群→极化→行动

## 配色系统（藏青主题）

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 | `#1A2B4A` | 标题、主数据系列、KPI数值 |
| 主色浅 | `#3d5a80` | 次要数据系列 |
| 辅助 | `#758092` / `#BABFC9` / `#DDE0E4` | 文字层级、对比系列、背景 |
| 风险 | `#c0392b` | 供给空白、风险、关键占比折线 |
| PPT标题红 | `rgb(192,0,0)` | PPT专用深红标题和强调 |

**原生XML映射**：主色→blue/light-blue，次要→gray/light-gray，风险→red/light-red。禁止在原生XML中用十六进制颜色。

## 交付前检查清单

- [ ] 开头 callout 能独立回答核心问题（≤300字）
- [ ] "一图看懂"HTML5 block 存在且渲染正常
- [ ] 每个一级标题下至少一个可视化元素
- [ ] 所有关键数字经过至少2个权威来源交叉核实，核实状态已记录
- [ ] 汽车行业数据已通过太平洋汽车/易车/车主之家/乘联会等平台核实（其他行业按映射表执行）
- [ ] 推算值已标明口径和推算方法，未与已证实事实混淆
- [ ] 矛盾/不确定信息已通过 interaction.ask 获得用户确认，确认记录已留存
- [ ] 配色统一为藏青主题，无混用
- [ ] 报告末尾"参考来源"章节包含：数据核实说明（核实平台、数据截止日期、用户确认事项）+ 按编号排列的引用来源（含发布方、标题、日期、完整链接），整体块严格左对齐贴边，不居中、不两端对齐
- [ ] 正文引用编号与末尾来源列表一一对应
- [ ] 结尾有 callout 或行动建议
- [ ] 报告尾部备注：分析人姓名 + 生成日期时间，与正文同样严格左对齐贴边，不居中
- [ ] PPT（如有）每页一观点、深红标题左对齐、无装饰图片
