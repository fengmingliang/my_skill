# 我的研究报告模板

固化的格式规范、配色系统和分析结构，确保每次输出风格一致、图文并茂、结论先行。

## 工作流程

### 1. 决策简报（先想清楚再动笔）

动笔前明确以下信息，能从上下文推断的不追问：

| 字段 | 要回答的问题 |
|---|---|
| 核心问题 | 这份报告要回答什么决策问题？ |
| 读者 | 谁会据此拍板？关注什么？ |
| 交付物 | 飞书文档？PPT？HTML可视化页？还是组合？ |
| 数据来源 | 已有哪些数据？需要补充搜索什么？ |
| 关键假设 | 哪些是推算值？哪些是已证实事实？ |

### 2. 证据底稿（事实门）

关键事实必须可追溯。为每条事实分配 ID（如 [F1]），记录：
- 原子事实内容
- 状态：已证实 / 推算 / 待验证 / 产品建议
- 直接来源（标题、发布方、日期、链接）
- 支持的结论

**事实闸门不通过的情况**：没有原始链接、数字无口径、把"即将推出"当现状、对比表无来源。不通过则删除该主张或降级为待验证。

### 3. 数据交叉核实与用户确认（核实门）

**本步骤为强制环节，所有关键数据必须通过后方可进入大纲设计。**

按 `references/data-verification.md` 执行：

1. **识别关键数据**：从证据底稿中提取所有具体数字、排名断言、政策条款、竞品参数，标记为"必须核实"
2. **双源交叉验证**：按行业权威平台映射表，在至少 2 个独立权威来源中核实每个关键数据
   - 汽车行业：太平洋汽车、易车、汽车之家、车主之家、乘联会、中汽协等
   - 其他行业：按 `references/data-verification.md` 中的映射表执行
3. **记录核实状态**：在证据底稿中为每条事实追加"来源1/来源2/核实状态"字段
4. **用户确认门**：遇到以下情况必须暂停，使用 `interaction.ask` 向用户确认后再继续：
   - 两个权威来源数据差异 >5%
   - 口径/定义/时间范围冲突
   - 核心结论依赖的数据无权威来源
   - 用户提供数据与公开数据冲突
   - 政策/法规不确定或存在多种解读
   - 涉及未公开的竞品敏感信息
5. **确认后记录**：用户选择后在证据底稿中记录"用户确认：选择X，时间"，确认数据方可进入正文

**核实门不通过的情况**：关键数据单源且无补充、矛盾数据未经用户确认、推算值未标注口径。不通过则该数据不得用于核心结论。

### 4. 大纲设计（演绎式结构）

按 `references/structure-template.md` 的标准章节组织：
开头 callout → **模块化目录** → 一图看懂 → 范围口径 → 现状趋势 → 核心分析（2-4节）→ 排除法反证 → 空间估算 → 行动建议 → 参考来源。

每节先给结论，再给证据。连续纯正文不超过500字，必须插入可视化元素。

**模块化目录（报告开头必做）**

在核心结论 callout 之后、正文第一章节之前，必须放一个"目录大纲"模块，按卡片网格呈现，禁止退回纯文字 `<ol>` 列表：

1. **卡片四要素**：模块编号（M1、M2…）+ 章节标题 + 一句话说明"这节解决什么问题"（用问句或判断句）+ 该节的可视化形式（如"折线图 + 表格"）。不复述结论数字，避免与正文重复。
2. **排布**：等宽等高卡片，2–4 列网格（正文宽 ≥1000px 用 3–4 列，窄屏 1–2 列），白底、1px 浅灰边框、左侧 3px 藏青色条，编号用浅灰大字压角。
3. **数量**：4–8 个模块；超过 8 个先合并章节，不要压成两行小字。目录模块本身不计入"一图看懂"的可视化配额。
4. **可跳转**：卡片包成 `<a href="#m1">`，对应章节 `<h2 id="m1">`，纯静态锚点，不引入 JS。锚点跳转属静态 HTML 能力，不受"不加动态特性"限制。
5. **一致性**：卡片标题取自正文 `h2` 的核心短语（一般取冒号前的主干，如"双减后的格局"），不得自造与正文无关的标题；正文增删章节后必须同步改目录，交付前核对。
6. **表头一句**：目录块上方加一行小标题（如"报告结构 · 6 个模块"），写明模块总数，便于读者建立预期。

### 5. 可视化制作（静态 SVG 优先）

**【核心原则】默认静态图，默认不用 ECharts**

1. **静态图用内联 SVG 插入**：所有图表直接写在 HTML 里的 `<svg viewBox="0 0 W H">`，不依赖任何图表库、不引用 CDN、不引用本地 `echarts.min.js`。报告必须是**完全自包含的单文件 HTML**，离线、转发、下载后都能正常显示。
2. **能不用 ECharts 就不用**：柱状、条形、折线、面积、饼图、环形、堆叠、散点、漏斗、热力等常见图，全部用内联 SVG + CSS 手工绘制。
3. **原本"必须用 ECharts"的场景，用 HTML 原生图表绘制替代**：不引入库、不写 `setOption`。需要多序列、双轴、堆叠时，用 SVG 的坐标计算 + `<rect>`/`<path>`/`<text>` 组合实现，几何参数在脚本里算好再拼进 SVG，或直接手算坐标写死。
4. **不默认加动态特性**：不加 hover tooltip、图例联动、入场动画、缩放拖拽、筛选控件。静态图能满足日常阅读、汇报、打印即可。**只有用户明确要求"交互/可点击/动态演示"时**才加，且只用原生 JS/CSS 实现，仍不引入外部库。
5. **图表必须自解释**：每张图自带图题、单位、坐标轴刻度或数值标签、数据来源脚注；脱离正文也能读懂。

**图表选型（全部用 SVG 实现）**

| 数据关系 | 推荐图形 | SVG 实现要点 |
|---|---|---|
| 时间趋势 | 折线 / 面积 | 按比例映射 x、y 坐标，`<path>` 连点，标注峰谷数值 |
| 多对象对比 | 横向条形 | 条长按最大值归一，右端标数值，条数多时用横向 |
| 结构占比 | 环形 / 堆叠条 | 环形用 `<path>` 算扇形角度；堆叠条按累计宽度分段 |
| 排序与分布 | 排序条形 + 参考线 | 加均值/中位数虚线，突出异常项 |
| 区间对比 | 悬浮区间条 | 用一段粗条表示上下限，中点标中位数 |
| 流程与路径 | SVG 矩形 + 箭头 | 节点等宽对齐，箭头方向统一自左向右 |

**SVG 制作硬要求**

- 根元素写 `<svg viewBox="0 0 W H" role="img" aria-label="图表标题" style="width:100%;height:auto">`，`viewBox` 宽高比与实际容器一致，避免文字被拉伸。
- 字号：图题 13px、轴标签 11px、数据标签 10–11px、来源脚注 10px；正文不小于 14px。
- 颜色只用藏青主题色板（主色 `#1A2B4A`、次色 `#3d5a80`、辅助 `#758092`/`#BABFC9`、风险 `#c0392b`）；序列区分除颜色外必须再加直接数值标注，禁止只靠颜色。
- 文字不得旋转、不得压线、不得超出 `viewBox`；标签放不下时优先减少标签数量、改横向条形、或把数值直接标在条端，不得缩小到 9px 以下。
- 坐标轴必须有刻度值与单位；无坐标轴的图形（如环形图）必须标百分比与合计口径。
- 图表下方保留一行来源与口径说明（同正文左对齐）。

**承载方式**

- **独立 HTML 报告（默认交付）**：直接内联 `<svg>` + 内联 CSS，单文件交付。
- **飞书文档内嵌**：用 html5-block 承载内联 SVG，同样不引用任何外部库。
- **PPT**：图表用幻灯片原生图表或 `<embed>` 内联 SVG，规则见 `references/ppt-spec.md`。
- **表格**：用于精确对比，表头浅灰，数值右对齐，关键差异用红色标注。
- **配色**：严格遵循 `references/format-spec.md` 的藏青色板。

**HTML 布局对齐**

footer（参考来源、注释、分析人备注）必须与正文 `.container` 保持同样的 `max-width:1200px;margin:0 auto;padding:32px 24px`，整体块贴左边距，不居中、不贴屏幕边；正文与尾部内容的左右边界必须严格一致。

**渲染自检（必做）**

- 用 headless Chromium（`chromium-browser --headless --screenshot`）打开报告截图，逐张确认 SVG 图表完整显示：坐标轴、标签、数值、单位齐全，文字无重叠无截断，无空白图框。
- 用 `node --check` 校验脚本语法（如有脚本）；SVG 结构可用 XML 解析器校验一遍是否闭合正确。
- 发现空白、错位、文字溢出必须修复后重新截图，禁止未验证直接交付。

### 6. 生成与校验

1. 用 lark-cli docs +script init-draft 初始化
2. 写入完整 XML（含 html5-block 引用）
3. 运行 parse 校验
4. 创建飞书文档
5. 回读确认：HTML5 block 数量、表格数量、callout 数量、章节结构

### 7. PPT 制作（如需要）

按 `references/ppt-spec.md` 的轻商务清爽风格：
- 白底、微软雅黑、深红标题左对齐
- 每页一观点，论证素材平均分布
- 10页左右：封面→核心结论→现状→市场→案例→空间→竞品→人群→极化→行动

## 配色系统（藏青主题）

| 角色 | 色值 | 用途 |
|---|---|---|
| 主色 | `#1A2B4A` | 标题、主数据系列、KPI数值 |
| 主色浅 | `#3d5a80` | 次要数据系列 |
| 辅助 | `#758092` / `#BABFC9` / `#DDE0E4` | 文字层级、对比系列、背景 |
| 风险 | `#c0392b` | 供给空白、风险、关键占比折线 |
| PPT标题红 | `rgb(192,0,0)` | PPT专用深红标题和强调 |

**原生XML映射**：主色→blue/light-blue，次要→gray/light-gray，风险→red/light-red。禁止在原生XML中用十六进制颜色。

## 交付前检查清单

- [ ] 开头 callout 能独立回答核心问题（≤300字）
- [ ] 开头有模块化目录：卡片网格（非纯文字列表），每卡含编号 M1…Mn、章节标题、"这节解决什么问题"、可视化形式；卡片数与正文一级标题一一对应
- [ ] 目录卡片标题取自正文 `h2` 主干，一一对应，`<a href="#mN">` 能跳转到对应 `#mN` 章节
- [ ] "一图看懂"HTML5 block 存在且渲染正常
- [ ] 所有图表为内联静态 `<svg>`，报告单文件自包含；全文无 `echarts`、`cdn.`、`unpkg`、`jsdelivr` 等外部依赖
- [ ] 每张图有图题、单位、坐标轴或数值标签、来源脚注；无文字重叠、无超出 viewBox
- [ ] 未叠加非必要交互（tooltip/动画/图例联动）；如加了，用户已明确要求
- [ ] 每个一级标题下至少一个可视化元素
- [ ] 所有关键数字经过至少2个权威来源交叉核实，核实状态已记录
- [ ] 汽车行业数据已通过太平洋汽车/易车/车主之家/乘联会等平台核实（其他行业按映射表执行）
- [ ] 推算值已标明口径和推算方法，未与已证实事实混淆
- [ ] 矛盾/不确定信息已通过 interaction.ask 获得用户确认，确认记录已留存
- [ ] 配色统一为藏青主题，无混用
- [ ] 报告末尾"参考来源"章节包含：数据核实说明（核实平台、数据截止日期、用户确认事项）+ 按编号排列的引用来源（含发布方、标题、日期、完整链接），整体块严格左对齐贴边，不居中、不两端对齐
- [ ] 正文引用编号与末尾来源列表一一对应
- [ ] 结尾有 callout 或行动建议
- [ ] 报告尾部备注：分析人姓名 + 生成日期时间，与正文同样严格左对齐贴边，不居中
- [ ] PPT（如有）每页一观点、深红标题左对齐、无装饰图片
